# Public guided AI

Disabled by default. This option changes which server can send a confirmed synthetic visitor question to the configured model. It does not grant the model approval authority or enable real banking, payments or counterparty messages.

The operator sets FLUXORA_PUBLIC_DEMO=1, FLUXORA_PUBLIC_AI=1 and FLUXORA_PUBLIC_AI_DAILY_LIMIT=1000 (valid range 1-1000) in the private runtime environment. CASHFLOW_MODEL_API_KEY, CASHFLOW_MODEL_BASE_URL and CASHFLOW_MODEL_NAME must all exist. Credentials stay server-side. Existing public installations with the flag absent remain model-free.

After a candidate passes synthetic qualification, its operator-owned shared qualification report enables the guided form for visitor workspaces. A real accepted model call verifies the in-process connection. Restart starts connection status unverified. Qualification expires after seven days and binds the credential/configuration identity, task contract, code, bundled skills and request policy. Do not copy a passing report across different configurations or code.

The guided composer shows provider/data disclosure before submission. Send sends the typed question for one bounded interpretation and immediately runs a validated read-only report or prepares DRAFT/pending work. Options → Preview before sending retains outbound preview and exact interpretation confirmation. One-step execution is not proof of semantic correctness: inspect the selected task and exact returned terms. Missing/unsafe/invalid instructions still stop without a draft. Final approval remains separate. One shared 30-second deadline covers interpretation and deterministic execution; no background worker or automatic retry is scheduled. A saved request identity replays its historical result before another provider call, including after restart. The provider receives only the typed question and static task definitions. The question itself can contain private data: use synthetic data only. Financial results and original attachments are not sent through this guided translation route. Arbitrary prose is discarded. DRAFTs and pending work require separate owner approval. Source observations and counterparty acceptance retain separate requirements.

The shared public provider-attempt counter lives in public-ai/usage.sqlite beside the base database, outside any visitor workspace. It resets by UTC date and survives server restart and visitor reset. Atomic reservations conservatively count attempts, including failed sends, with at most 1,000 daily. Requests use zero retries, 25-second transport timeout, a 30-second total budget, response-byte bounds and the existing provider token limits. One public adapter handles one in-flight request. A visitor may submit at most 20 translations per hour, with the existing global six-model-request/minute limit. These bound attempts, not currency cost, successful answers or provider uptime. Private Telegram model use is separate and is not included in this public counter.

Public visitors cannot run connection verification, repeat qualification or invoke the advanced live-agent loop. Those POST routes return 403. /agent redirects to the guided workflow. API and Telegram settings remain a static locked preview with no secret values. The floating assistant continues local guidance and hands questions to the same disclosed Agent path with Send and optional Options → Preview before sending. Telegram browser practice remains simulated and model-free.

Qualification and activation are operator tasks performed against a disposable candidate before rollout. Keep a private stopped-state backup and a previous image/configuration for rollback. Restore the previous environment only through the documented operator procedure. Keep counters and qualifications out of source archives. Independent user feedback and broad language accuracy remain separate validation work.
